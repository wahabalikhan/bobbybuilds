# Bobby Builds (HQ)

A public indie page showcasing Wahab and his projects, plus a private analytics dashboard at the admin path that every product reports to. Next.js App Router (TypeScript) on Cloudflare Workers via OpenNext, with Cloudflare D1.

## Rules (non-negotiable)

- No cookies and no personal data. Never store IP addresses, names or emails.
- Daily visitor ID = hash of today's secret + IP + user agent + project. Replace the secret daily and delete the old one.
- Product secret keys are stored only as hashes. Secrets never go in browser code, Git or NEXT_PUBLIC_ variables.
- /v1/pv only accepts requests from each project's registered origins, is rate limited, validates every field's type and length, stores only the referrer's domain, and sends nothing when Global Privacy Control is on.
- Every D1 query uses bound parameters. Every schema change is a migration.
- Public pages read only daily roll-ups, cached for 10 minutes. Raw page views and events are deleted after 90 days.
- Journey entries are Markdown, sanitised before display. Strict security headers, including a CSP, on every page.
- Plain, friendly copy in UK English.

## How we work

- Work in phases ([docs/roadmap.md](docs/roadmap.md)). Show a plan before each phase and wait for the go-ahead.
- At the end of each phase, update docs/roadmap.md (status and commit hashes), then stop, list what to test, and wait.
- Custom events are always sent with `bobby.track(name, props)`, in code, docs and instructions for connected products.
- Run `npm run verify` (check-env, typecheck, lint, tests) before every commit.

## Layout and conventions

- `src/lib/site.ts`: the only place for the site name, URL and admin path. Never hard-code them elsewhere; import `site` / `adminHref()`.
- `src/middleware.ts`: security headers on every page, and the Cloudflare Access JWT check for the admin path. It uses edge middleware rather than Next 16's `proxy.ts`, because OpenNext only officially supports edge middleware on Cloudflare. Ignore the deprecation warning.
- Admin pages live in `src/app/admin/`. If `site.adminPath` changes, the middleware rewrites the new path to it and hides `/admin`. Admin API routes also go under the admin path, so the same check covers them.
- `src/lib/security/`: CSP and headers (`headers.ts`) and the Access JWT check (`access.ts`).
- `migrations/`: D1 migrations (`npx wrangler d1 migrations create bobbybuilds-db <name>`). Apply with `npm run db:migrate:local` / `db:migrate:remote`.
- D1: always `env.DB.prepare(sql).bind(...)`. Never build SQL with string concatenation or template literals containing values.
- Schema conventions: tables are `STRICT`, and limits live in CHECK constraints as well as app validation.
  - Timestamps are INTEGER Unix ms. Days are UTC `'YYYY-MM-DD'`, checked with `day IS date(day)`. Use `IS`, never `=`: a NULL from `date()` would pass a CHECK.
  - Weeks start on Monday (`src/lib/days.ts`).
  - In roll-up key columns, `''` means "none".
  - Every new limit gets a test in `tests/schema.test.ts`.
- Query helpers live in `src/lib/db/`, taking a `D1Database`. `secret_key_hash` is never selected into app objects.
- Keys: `npm run keys:create -- <slug> [--remote] [--rotate]`. It shows the secret key once, stores only its SHA-256 hash, and writes through `getPlatformProxy` so the update is a bound query.
- Collector:
  - **Logic and routes:** the logic lives in `src/lib/collector/`, as handlers that take a `Request` plus `CollectorDeps`, so tests call them directly. `src/app/v1/*/route.ts` only pass requests through. `/v1` is outside the page middleware and sets its own headers.
  - **Browser requests** need a public key and an exact `Origin` match. **Server requests** need `Authorization: Bearer sk_…`, and a secret key that arrives with an `Origin` header is refused.
  - **Privacy signals:** GPC or DNT means 204 and nothing stored, in both the server and `t.js`.
  - **Rejected or dropped:** structural fields that fail validation get 400. Junk marketing fields (`ref`, `utm_*`, referrer) are dropped, and the page view is kept.
  - **Built-in browser events** need no allowlist: `outbound_click {domain}`, `file_download {file,type}`, `not_found`, `form_started {form}` and `form_submitted {form}`. Their prop shapes are exact (`BUILT_IN_EVENTS`).
- Tracker:
  - **Source and build:** the source is `src/tracker/`. `core.ts` is testable with happy-dom; `t.ts` is the entry point; `vitals.ts` (web-vitals) becomes `t-vitals.js`, which `t.js` loads after the page has loaded and which reports through `bobby._vital`. `public/t.js` and `public/t-vitals.js` are generated by `npm run build:tracker`, which runs before dev and build, and are not committed. Keep `t.js` under 6 KB (there's a test).
  - **What it collects:** no cookies or storage, and it never sends the query string except `ref` and `utm_*`.
  - **Download types:** keep `DOWNLOAD_TYPES` in sync between `core.ts` and `validate.ts`.
- Local collector testing: run `npm run preview` and `npm run playground`. The playground adds a local-only project with origin `http://localhost:5555`.
- Scheduled jobs:
  - **Logic:** lives in `src/lib/jobs/`, and `POST /internal/jobs` runs it (`run.ts`). The route needs `Authorization: Bearer <ROLLUP_SECRET>`, compared in constant time, and answers a plain 404 to anything else.
  - **Cron Worker:** `cron/` (`bobbybuilds-cron`) only triggers the jobs, through a service binding. It runs `*/5` for `frequent` (uptime; today's roll-up and the snapshot every 10 minutes; the GitHub contribution calendar on the hour) and 00:10 UTC for `daily` (finalise yesterday, rotate the secret, 90-day clean-up, GitHub weekly commits).
  - **Roll-ups** are rebuilt per day in one D1 batch, so running one again is safe. Every run is recorded in `job_runs`.
  - **Secrets:** `ROLLUP_SECRET` must be the same on both Workers, and `npm run deploy` / `deploy:cron` refuse without it. `GITHUB_TOKEN` (read-only Contents, selected repos only) is set on `bobbybuilds` only.
  - **Changing `ROLLUP_SECRET`:** set the new value on both Workers in one go, without printing it.
- Admin dashboard:
  - **Purpose:** set projects up, then glance at them occasionally. Every page answers the key questions at a glance (is everything OK, how are the projects doing, who's looking at the portfolio, is Tech Jobs working and what do people search for), with detail tucked away.
  - **Top bar:** only "Bobby Builds HQ" (Home) and the status pill (`StatusMenu`): green "● Everything's running normally", or amber/red "<n> things need attention", which opens the list (down, failed job runs in the last day with their error, no page views in 24 hours from a live site, missing keys). No Needs attention block on the page, and no Settings link.
  - **Home** (`src/app/admin/page.tsx`): the public page's own visitors card (`HeadlineCard`), then "My projects (<count>)" with a "+" (the New project setup at `/admin/projects/new`), then the project cards (visitors and change, the public numbers line, sparkline, uptime), then the retention line in small print.
  - **A project** (`src/app/admin/projects/[slug]/`): a breadcrumb back to Home and two tabs (`tabs.ts`). **Overview** (`overview.tsx`), one scrolling page: visitors with change and a sparkline (small range picker), top 5 pages and sources (in plain words: `sourceName`), tracked links when any have visits (one list of ?ref= and UTM links, each with what its visitors read: `trackedLinks`; never the word "campaigns"), searches (projects that send `search` events), the funnel as one line, health as one line (uptime over 90 days and broken links, amber or red only when there's a problem), then "More detail", closed by default (full tables, funnel, 404s, uptime strip and outages, the link builder, events and CSV). **Settings** (`settings.tsx`): About this project (name, tagline, status, site address), On your public page (switches), Connection (closed by default: snippet, allowed websites, events, funnel steps, secret key, product numbers), and Delete this project at the very bottom. Old `?tab=` values land on the Overview; the old `/admin/settings…` addresses redirect to the matching place.
  - **Test projects** (only loopback origins, like the local Playground) are hidden everywhere: admin lists, the status pill and the public snapshot (`isTestProject`, `listRealProjects`).
  - **Where things live:** pages in `src/app/admin/`. Queries in `src/lib/db/dashboard.ts` and `funnel.ts`. Charts in `src/components/charts.tsx`: server-rendered SVG with no chart library, a native `<title>` hover on each mark, and a table view for every chart. (The public page has its own charts: see Public pages.)
  - **Data sources:** charts read the roll-ups. The funnel, what a ref read, searches, 404s, outbound clicks, downloads, events and CSV read raw data, so the last 90 days only (`clampToRaw`). Everything is still collected, including what the dashboard no longer shows (countries, devices, browsers, Core Web Vitals, form events). Uptime checks the site address (`health_url`, `github_repo` and `logo_path` are kept in the database but unused, and kept when settings are saved). The per-repo GitHub weekly commits job was removed; the public contributions graph stays.
  - **Hidden way in:** there's no visible admin link on the public site. Option + A (Alt + A on Windows) on any public page, or five quick taps on the footer's copyright line, opens the admin path, and Option + A on any admin page goes back to the public site (`src/lib/public/admin-shortcut.ts`, `src/components/public/admin-shortcut.tsx`). The shortcut uses `event.code` (Option + A types "å"), and is ignored with other modifiers held or while typing in a field. It only navigates: Cloudflare Access and the JWT check stay the real protection.
  - **Re-check access:** every admin server action and route calls `requireAdmin()` / `isAdminRequestFrom()` (`src/lib/admin/access.ts`), because server actions can be invoked from any page.
  - **Local data:** `npm run seed:demo` fills the local database only, and refuses `--remote`.
  - **Live data:** `npm run admin:live` runs the dashboard on `127.0.0.1:8788` against the live database, with a red LIVE DATA banner. It uses a throwaway config (`scripts/lib/admin-live-config.mjs`) with its own Worker name. Never bind it to anything but loopback.
  - **Design tokens:** in `src/app/globals.css`. `--accent` is a placeholder until Phase 6, and status colours always come with an icon and a label.
- Settings (the Settings tab and the New project setup):
  - **Server actions:** in `src/app/admin/settings/actions.ts`. Each one's first line is `await requireAdmin();`, and `tests/node/actions.test.ts` enforces it. A `"use server"` file may export only actions.
  - **Logic:** in `src/lib/admin/settings-core.ts`, which takes `db` and form values, with no Next.js. Validation is in `src/lib/admin/validate.ts`, and writes in `src/lib/db/settings.ts`.
  - **Forms:** use `<SettingsForm>` and its fields (`src/components/admin/form.tsx`), which handle field errors, keeping what was typed, and showing a new secret key once.
  - **New project:** three steps (`NewProjectWizard`, `/admin/projects/new`): name and site address (slug and allowed origin worked out: `validateNewProject`, `startProjectCore`, which also makes the keys; the slug is never "new"), the snippet, then "Waiting for your first visit…", polling the admin-only `/admin/projects/<slug>/first-visit` route every 5 seconds. A secret key for server events is made later under Connection.
  - **Hidden:** Milestones and the System page are gone; the Journey editor (`/admin/settings/journey`) shows "not found" until `site.showJourney` is true.
  - **Logos:** automatic: `public/logos/<slug>.*` (`logoFor`), listed into `src/lib/logos.generated.ts` by `npm run build:logos`, which runs before dev, build and typecheck. There's no logo picker. Icons have no container: no background, border, outline or rounded clipping; each keeps its own shape (Portfolio's circle, Tech Jobs' square) in a fixed invisible box with `object-fit: contain`. Use files at least 2× the display size. Originals live in `public/logos/originals/` (not listed).
  - **Markdown:** `src/lib/markdown.ts`. Raw HTML is always escaped, links are http(s), mailto or same-site paths only, and images are same-site only. Use it for journey entries and project descriptions everywhere.
- Public pages:
  - **Routes:** `/`, `/journey`, `/journey/[slug]`, share images, `/sitemap.xml` and `/robots.txt`. There are no project pages: project cards open the project's own site in a new tab (↗), and `/p/*` redirects permanently to `/` (`next.config.ts`). The journey is hidden while `site.showJourney` is false: no home section, no header link, no sitemap entries, and `/journey/*` redirects (temporarily) to `/`. Its code, table and admin editor stay; set it to true and deploy to bring it back.
  - **Interactive pieces:** `src/components/public/charts.tsx` (the custom project dropdown, monthly bars and card sparklines, each with a hover popover) and `github.tsx` (the contribution grid). They only use figures already in the page. Each chart has a screen-reader-only table instead of a visible "Show as a table".
  - **Data:** they read ONLY the public snapshot (`getSnapshot()` in `src/lib/public/`), never `@/lib/db` or bindings. `tests/node/public-boundary.test.ts` enforces this.
  - **What's public:** each project's visitors (the public chart and its card's sparkline) and each product number (the card's line, e.g. "1,240 open jobs · 300 companies": latest daily values with commas, labelled in lower case, hidden when the newest is over 7 days old: `productLine`). The same line shows on the admin card and dashboard header.
  - **Wordmark:** the profile panel starts with the favicon's dark square and "Bobby Builds" (`Wordmark`), so "by Bobby Builds" visitors know they're in the right place. There's no navigation bar.
  - **The snapshot:** built only from roll-ups, public numbers, published entries, public milestones and the GitHub contribution calendar (`github_contributions`, public data fetched hourly by the frequent job with `GITHUB_TOKEN`; a failed fetch keeps the last good year) (`src/lib/public/snapshot.ts`). Bump `SNAPSHOT_VERSION` when its shape changes. It's stored in KV (`PUBLIC_CACHE`) and written only when its content changes.
  - **When it's rebuilt:** by the 5-minute job every 10 minutes, by the daily job, and after every successful settings save. That's at most about 144 KV writes a day, against the free plan's 1,000. Don't add per-page KV writes.
  - **Indexing:** `site.indexable` (`src/lib/site.ts`) controls it. While false, there's noindex in the meta tag and the `X-Robots-Tag` header, and `robots.txt` disallows everything. Launch means setting it to true.
  - **Owner details** (name, full name for the copyright, GitHub login, bio, links, photo; no location is shown) live in `owner` in `src/lib/site.ts`. The footer's tool icons are in `public/made-with/`. The photo is `public/profile.png` or `public/profile.jpg` (also `.jpeg`/`.webp`), detected at build into `PROFILE_PHOTO`; until one exists, the initial is shown.
- Retention: raw `page_views`, `events`, `uptime_checks` and `job_runs` are deleted after 90 days (a row from exactly 90 days ago stays). Roll-ups, including `daily_uptime` and the Core Web Vitals p75 columns, are kept. `github_contributions` holds GitHub's last year only (older days are deleted on each refresh).
- The package is `"type": "module"`, so every `.js`/`.ts` file is ESM. Don't add CommonJS files. If one is ever needed, name it `.cjs`.
- Tests: `npm test` runs Vitest inside the Workers runtime (`@cloudflare/vitest-plugin`) on a fresh D1 with every migration applied.
- Bindings: get them with `getCloudflareContext()` from `@opennextjs/cloudflare`. Run `npm run cf-typegen` after changing `wrangler.jsonc`.

## Design (every page, public and admin)

The reference is `marclou.pdf` (Marc Lou's indie page). Use the same structure and feel, with our own accent colour and content, and never his brand.

- **Page:** a clean white background, generous spacing, Geist. Every page, public and admin (and the admin top bar), uses the one container `PAGE` (`src/lib/layout.ts`: 1040px, the same side padding and centring), so nothing shifts between them. Inner content may be narrower, never wider. Wide content (tables, code) truncates or scrolls inside its own box; `tests/node/layout.test.ts` checks the container. The public site is light only. The admin dashboard alone has a dark version (`.admin-theme` in `globals.css`, by the system setting).
- **Cards:** white, with thin light-grey borders (`border-line`) and 16px corners (`rounded-2xl`). No heavy shadows.
- **Section headings:** small, with a hairline underneath and a count or link on the right (`SectionHeading`).
- **Numbers:** small rounded grey pills, e.g. "2,731 visitors" (`Pill`).
- **Buttons:** black pills (`buttonClass`); secondary actions use `quietButtonClass`.
- **Charts:** monochrome. Sparklines and time series have a light-grey fill and a dark line, and the latest unfinished period is dashed (`unfinishedLast`). Bars are dark, and the unfinished one is lighter. The one exception is the public GitHub grid, in GitHub's own greens (`--gh-0` … `--gh-4`, with dark-mode versions).
- **Popovers (public page):** white cards with a thin border and soft shadow: a bold heading (month or week), then rows of project logo, grey name and value, and a TOTAL row when there's more than one.
- **Overview pages:** start with a big full headline number plus a bar chart card, with a dropdown pill top right.
- **Layout:** two-column card grids for projects. (Ideas and retired projects aren't shown on the public page for now.)
- **Accent colour:** `--accent` (placeholder until Phase 6) is only for interactive states: focus, links and selection. It's never used for chart marks.
- **Statuses:** reserved colours, always with an icon and a label.

## Security headers and CSP

- Public pages are cached, so they get a fixed CSP with no nonce (`script-src 'self' 'unsafe-inline'`, plus `default-src 'self'`, `base-uri 'none'`, `object-src 'none'`, `frame-ancestors 'none'`, `form-action 'self'`, `connect-src 'self'`). Never add third-party scripts to public pages. Never render unsanitised HTML.
- Admin pages render per request (`await connection()` in the admin layout) with a per-request nonce and `'strict-dynamic'`. Admin responses are `Cache-Control: private, no-store`.
- If a public page needs a third-party origin (for example Buttondown for the build updates form), add it to the specific directive only.

## Secrets

- Local: `.dev.vars` (ignored by Git). Production: `npx wrangler secret put NAME`. Names only in `.dev.vars.example`.
- Never in `.env*`, `NEXT_PUBLIC_*`, `wrangler.jsonc` vars, or Git. `npm run check-env` runs before build, deploy, upload and preview, and refuses if this is broken.
- `ACCESS_TEAM_DOMAIN` and `ACCESS_AUD` are not secret and live in `wrangler.jsonc` vars. The admin path refuses every request while either is empty.
- Live /admin sits behind a path-based Access app on `bobbybuilds.app` (`admin`, `admin/*`), and the JWT check still runs behind it. Locally, `LOCAL_ADMIN_PREVIEW=on` in `.dev.vars` opens it with `npm run preview`, on loopback hostnames only (`src/lib/security/local-admin.ts`). Never weaken the loopback check or move the flag anywhere else. check-env enforces this.

## Deploying

- Lives at `https://bobbybuilds.app` (a Workers custom domain on the bare domain only). workers.dev and preview URLs are off (`workers_dev: false`, `preview_urls: false`), and a test keeps them off.
- `npm run deploy`. Domain and Access setup steps are in `docs/access-setup.md`.

## Domain plan (bobbybuilds.app)

Keep these free. Nothing in HQ may get in their way:

- `bobbybuilds.app`: HQ. Its route is the exact domain, never `*.bobbybuilds.app/*`. The Access app covers only its `admin` and `admin/*` paths, never a wildcard hostname.
- `www.bobbybuilds.app`: a 301 redirect to the bare domain (a proxied `AAAA 100::` record and a Redirect Rule).
- `techjobs.bobbybuilds.app`: the job board, "Tech Jobs, by Bobby Builds", on its own Worker custom domain (repo ~/Desktop/job_board).
- Email: one address, `hello@bobbybuilds.app`, for sending and receiving. There's no `mail.` subdomain.
  - **Receiving:** Cloudflare Email Routing forwards hello@ to a personal inbox. It owns the bare domain's 3 MX records, its SPF TXT (`v=spf1 include:_spf.mx.cloudflare.net ~all`) and DKIM `cf2024-1._domainkey`.
  - **Sending:** Resend, verified on the bare domain (eu-west-1). TXT `resend._domainkey` (DKIM), CNAME `send` → `send.forge.rmta.net` and CNAME `rsend` → `rsend-euw1.forge.rmta.net`, all DNS only. Resend's SPF and bounce handling sit behind those CNAMEs, never at the bare domain. Resend's Receiving stays off (it would need the bare domain's MX), and click and open tracking stay off.
  - **There must only ever be one SPF record at the bare domain** (Email Routing's). Never add a second one; if something else ever needs it, merge it into that one record.
  - **DMARC:** TXT `_dmarc` `v=DMARC1; p=none; rua=mailto:hello@bobbybuilds.app`. Move to `p=quarantine` after a couple of weeks of clean reports.
- Keep Bot Fight Mode off: on the Free plan it can't skip particular paths, and it would challenge server requests to `/v1`.
- Build updates email form (Phase 6) posts straight to an external newsletter tool (such as Buttondown). HQ never sees or stores the address.
