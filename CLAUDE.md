# BobbyBuilds (HQ)

A public indie page showcasing Wahab and his projects, plus a private analytics dashboard at the admin path that every product reports to. Next.js App Router (TypeScript) on Cloudflare Workers via OpenNext, with Cloudflare D1.

## Rules (non-negotiable)

- No cookies and no personal data. Never store IP addresses, names or emails.
- Daily visitor ID = hash of today's secret + IP + user agent + project. Replace the secret daily and delete the old one.
- Product secret keys are stored only as hashes. Secrets never go in browser code, Git or NEXT_PUBLIC_ variables.
- /v1/pv only accepts requests from each project's registered origins, is rate limited, validates every field's type and length, stores only the referrer's domain, and sends nothing when Global Privacy Control is on.
- Every D1 query uses bound parameters. Every schema change is a migration.
- Public pages read only daily roll-ups, cached for 10 minutes. Raw page views and events are deleted after 90 days.
- Journey entries are Markdown, sanitised before display. Strict security headers, including a CSP, on every page.
- Plain, friendly copy in UK English.

## How we work

- Work in phases ([docs/roadmap.md](docs/roadmap.md)). Show a plan before each phase and wait for the go-ahead.
- At the end of each phase, update docs/roadmap.md (status and commit hashes), then stop, list what to test, and wait.
- Custom events are always sent with `bobby.track(name, props)`, in code, docs and instructions for connected products.
- Run `npm run verify` (check-env, typecheck, lint, tests) before every commit.

## Layout and conventions

- `src/lib/site.ts`: the only place for the site name, URL and admin path. Never hard-code them elsewhere; import `site` / `adminHref()`.
- `src/middleware.ts`: security headers on every page, and the Cloudflare Access JWT check for the admin path. It uses edge middleware rather than Next 16's `proxy.ts`, because OpenNext only officially supports edge middleware on Cloudflare. Ignore the deprecation warning.
- Admin pages live in `src/app/admin/`. If `site.adminPath` changes, the middleware rewrites the new path to it and hides `/admin`. Admin API routes also go under the admin path, so the same check covers them.
- `src/lib/security/`: CSP and headers (`headers.ts`) and the Access JWT check (`access.ts`).
- `migrations/`: D1 migrations (`npx wrangler d1 migrations create bobbybuilds-db <name>`). Apply with `npm run db:migrate:local` / `db:migrate:remote`.
- D1: always `env.DB.prepare(sql).bind(...)`. Never build SQL with string concatenation or template literals containing values.
- Schema conventions: tables are `STRICT`, and limits live in CHECK constraints as well as app validation.
  - Timestamps are INTEGER Unix ms. Days are UTC `'YYYY-MM-DD'`, checked with `day IS date(day)`. Use `IS`, never `=`: a NULL from `date()` would pass a CHECK.
  - Weeks start on Monday (`src/lib/days.ts`).
  - In roll-up key columns, `''` means "none".
  - Every new limit gets a test in `tests/schema.test.ts`.
- Query helpers live in `src/lib/db/`, taking a `D1Database`. `secret_key_hash` is never selected into app objects.
- Keys: `npm run keys:create -- <slug> [--remote] [--rotate]`. It shows the secret key once, stores only its SHA-256 hash, and writes through `getPlatformProxy` so the update is a bound query.
- Collector:
  - **Logic and routes:** the logic lives in `src/lib/collector/`, as handlers that take a `Request` plus `CollectorDeps`, so tests call them directly. `src/app/v1/*/route.ts` only pass requests through. `/v1` is outside the page middleware and sets its own headers.
  - **Browser requests** need a public key and an exact `Origin` match. **Server requests** need `Authorization: Bearer sk_…`, and a secret key that arrives with an `Origin` header is refused.
  - **Privacy signals:** GPC or DNT means 204 and nothing stored, in both the server and `t.js`.
  - **Rejected or dropped:** structural fields that fail validation get 400. Junk marketing fields (`ref`, `utm_*`, referrer) are dropped, and the page view is kept.
  - **Built-in browser events** need no allowlist: `outbound_click {domain}`, `file_download {file,type}`, `not_found`, `form_started {form}` and `form_submitted {form}`. Their prop shapes are exact (`BUILT_IN_EVENTS`).
- Tracker:
  - **Source and build:** the source is `src/tracker/`. `core.ts` is testable with happy-dom; `t.ts` is the entry point; `vitals.ts` (web-vitals) becomes `t-vitals.js`, which `t.js` loads after the page has loaded and which reports through `bobby._vital`. `public/t.js` and `public/t-vitals.js` are generated by `npm run build:tracker`, which runs before dev and build, and are not committed. Keep `t.js` under 6 KB (there's a test).
  - **What it collects:** no cookies, and it never sends the query string except `ref` and `utm_*`. Its only storage is reading one localStorage flag on the owner's own browser.
  - **Don't count my visits** (`src/tracker/ignore.ts`): `bobby_ignore` in localStorage, per site and per browser. Opening any page with `#bobby-ignore` sets it (t.js says so with a message and drops the hash) and `#bobby-count` clears it. The switch at the bottom of admin Home sets it for bobbybuilds.app and lists the `#bobby-ignore` link for each other site. While it's set, t.js sends nothing, like GPC.
  - **Download types:** keep `DOWNLOAD_TYPES` in sync between `core.ts` and `validate.ts`.
- Local collector testing: run `npm run preview` and `npm run playground`. The playground adds a local-only project with origin `http://localhost:5555`.
- Scheduled jobs:
  - **Logic:** lives in `src/lib/jobs/`, and `POST /internal/jobs` runs it (`run.ts`). The route needs `Authorization: Bearer <ROLLUP_SECRET>`, compared in constant time, and answers a plain 404 to anything else.
  - **Cron Worker:** `cron/` (`bobbybuilds-cron`) only triggers the jobs, through a service binding. It runs `*/5` for `frequent` (uptime; today's roll-up and the snapshot every 10 minutes) and 00:10 UTC for `daily` (finalise yesterday, rotate the secret, 90-day clean-up, the GitHub contribution calendar for the shipping rhythm).
  - **Roll-ups** are rebuilt per day in one D1 batch, so running one again is safe. Every run is recorded in `job_runs`.
  - **Secrets:** `ROLLUP_SECRET` must be the same on both Workers, and `npm run deploy` / `deploy:cron` refuse without it. `GITHUB_TOKEN` (read-only Contents, selected repos only) is set on `bobbybuilds` only.
  - **Changing `ROLLUP_SECRET`:** set the new value on both Workers in one go, without printing it.

## Design (every page, public and admin)

Phase 11 brings the admin onto the public page's design language, so the two share one design system (tokens, typography, status dots, links, focus, charts and cards).

Our own, designer-led look: black, grey and white with one sparing accent blue, muted and calm, with plenty of space and strong typography. The public page is a single column (never a profile panel beside a project grid). Otherwise colour only marks a type or status (journey emojis, status dots) or belongs to a brand (the profile's LinkedIn and GitHub icons, the footer's tool icons). It never decorates.

- **Tab titles:** the page's name first, then the brand. The public layout's template adds " · BobbyBuilds" ("Page not found · BobbyBuilds"), the admin layout's adds " · BobbyBuilds HQ" ("Tech Jobs · BobbyBuilds HQ", "Tech Jobs settings · BobbyBuilds HQ", "New project · BobbyBuilds HQ"), so pages set only their own name. The home page is "BobbyBuilds · Wahab (Bobby) Khan" (`homeTitle`, also the share image's title), and admin Home is "BobbyBuilds HQ" (`adminName`). `test:admin-live` checks them.
- **Page:** a clean white background, generous spacing, Geist. Every page, public and admin (and the admin top bar), uses the one container `PAGE` (`src/lib/layout.ts`: 900px, the same side padding and centring), so nothing shifts between them. Inner content may be narrower, never wider. Wide content (tables, code) truncates or scrolls inside its own box; `tests/node/layout.test.ts` checks the container. Both have a dark version, by the system setting: public pages are wrapped in `.public-theme` (the tokens are set on `:root:has(.public-theme)`, so the page background follows) and the admin in `.admin-theme`. Text is at least 4.5:1 in both.
- **Cards:** white, with thin light-grey borders (`border-line`) and 16px corners (`rounded-2xl`). No heavy shadows.
- **Section headings:** small, with a hairline underneath and a count or link on the right (`SectionHeading`).
- **Numbers:** plain bold figures (`text-3xl font-semibold` for headline figures, `font-semibold` inline), public and admin. The small grey pills (`Pill`) are only for dense lists and tables (journey Published/Draft, event names).
- **Buttons:** black pills (`buttonClass`); secondary actions use `quietButtonClass`.
- **Charts (public and admin):** marks are the accent blue (`--chart-line`, `--chart-bar`; this month's bar a lighter blue, `--chart-soft`), over a light grey fill, with grey axes, gridlines and labels; comparison ("previous period") lines are grey (`--previous`); the latest unfinished period is dashed or lighter. Uptime keeps its status colours, the GitHub grid uses blues, and the public honest-numbers trend stays neutral (`--chart-neutral`). Every chart has the same ink hover card (`HOVER_CARD` in `src/lib/chart-style.ts`): the client charts (`mono-charts.tsx`, `public/charts.tsx`) show it with React, the admin's server-rendered SVG charts (`src/components/charts.tsx`) with invisible CSS hover areas over the chart (`HoverArea`), so they still need no client JavaScript. No native `<title>` tooltips.
- **Admin Overview pages:** start with a big full headline number plus a bar chart card, with a dropdown pill top right.
- **Layout:** two-column card grids for projects in the admin; one column of large cards on the public page. (Ideas and retired projects aren't shown on the public page for now.)
- **Accent colour:** one accent blue for the public pages and the admin, defined once in `globals.css` and used sparingly: `--accent` #2747D6 (7.1:1 on white) and #8199F8 in dark mode (7.4:1 on the page, 7.05:1 on cards), with `--accent-selection` for the selected-text tint. For: text links on hover (they're ink and underlined at rest, so they're links without the colour); a project card's title and ↗ on hover and focus; focus outlines; chart lines and bars; the GitHub grid's levels; and text selection. Never backgrounds or filled buttons, and never the status dots or brand icons.
- **Brand colours:** the public profile's LinkedIn and GitHub icons are always in their brand colours (`--brand-linkedin` #0A66C2, 5.7:1 on white, and #70B5F9 in dark mode, 7.9:1; `--brand-github` black, white in dark mode). Email's icon is ink. The footer's tool icons are in their own colours.
- **Statuses:** reserved colours, always with a label. Status text uses the darker `--critical-ink` (#B42323, #F87171 in dark mode) and `--warning-ink` (#6B4600, #FCD34D in dark mode), at least 4.5:1 on white, the dark page and their tints; the red and amber themselves are for fills. Status icons' glyphs are 3:1 or more (dark on amber and orange, the page colour on grey). A project's status is `StatusDot` (`src/components/status-dot.tsx`) everywhere, public and admin: a coloured dot and its word.
- **Cursors:** the hand on everything clickable and not-allowed when disabled, from the base layer in `globals.css`. Nothing else gets the hand, and the footer's five-tap © line keeps the normal cursor. The Chrome click-through (`scripts/lib/admin-click-through.mjs`, whose `CLICKABLE` list matches the CSS) checks every page.

## Security headers and CSP

- Public pages are cached, so they get a fixed CSP with no nonce (`script-src 'self' 'unsafe-inline'`, plus `default-src 'self'`, `base-uri 'none'`, `object-src 'none'`, `frame-ancestors 'none'`, `form-action 'self'`, `connect-src 'self'`). Never add third-party scripts to public pages. Never render unsanitised HTML.
- Admin pages render per request (`await connection()` in the admin layout) with a per-request nonce and `'strict-dynamic'`. Admin responses are `Cache-Control: private, no-store`.
- If a public page needs a third-party origin (for example Buttondown for the build updates form), add it to the specific directive only.

## Secrets

- Local: `.dev.vars` (ignored by Git). Production: `npx wrangler secret put NAME`. Names only in `.dev.vars.example`.
- Never in `.env*`, `NEXT_PUBLIC_*`, `wrangler.jsonc` vars, or Git. `npm run check-env` runs before build, deploy, upload and preview, and refuses if this is broken.
- `ACCESS_TEAM_DOMAIN` and `ACCESS_AUD` are not secret and live in `wrangler.jsonc` vars. The admin path refuses every request while either is empty.
- Live /admin sits behind a path-based Access app on `bobbybuilds.app` (`admin`, `admin/*`), and the JWT check still runs behind it. Locally, `LOCAL_ADMIN_PREVIEW=on` in `.dev.vars` opens it with `npm run preview`, on loopback hostnames only (`src/lib/security/local-admin.ts`). Never weaken the loopback check or move the flag anywhere else. check-env enforces this.

## Domain plan (bobbybuilds.app)

Keep these free. Nothing in HQ may get in their way:

- `bobbybuilds.app`: HQ. Its route is the exact domain, never `*.bobbybuilds.app/*`. The Access app covers only its `admin` and `admin/*` paths, never a wildcard hostname.
- `www.bobbybuilds.app`: a 301 redirect to the bare domain (a proxied `AAAA 100::` record and a Redirect Rule).
- `techjobs.bobbybuilds.app`: the job board, "Tech Jobs, by BobbyBuilds", on its own Worker custom domain (its own repo, `job_board`).
- Email: one address, `hello@bobbybuilds.app`, for sending and receiving. There's no `mail.` subdomain.
  - **Receiving:** Cloudflare Email Routing forwards hello@ to a personal inbox. It owns the bare domain's 3 MX records, its SPF TXT (`v=spf1 include:_spf.mx.cloudflare.net ~all`) and DKIM `cf2024-1._domainkey`.
  - **Sending:** Resend, verified on the bare domain (eu-west-1). TXT `resend._domainkey` (DKIM), CNAME `send` → `send.forge.rmta.net` and CNAME `rsend` → `rsend-euw1.forge.rmta.net`, all DNS only. Resend's SPF and bounce handling sit behind those CNAMEs, never at the bare domain. Resend's Receiving stays off (it would need the bare domain's MX), and click and open tracking stay off.
  - **There must only ever be one SPF record at the bare domain** (Email Routing's). Never add a second one; if something else ever needs it, merge it into that one record.
  - **DMARC:** TXT `_dmarc` `v=DMARC1; p=none; rua=mailto:hello@bobbybuilds.app`. Move to `p=quarantine` after a couple of weeks of clean reports.
- Keep Bot Fight Mode off: on the Free plan it can't skip particular paths, and it would challenge server requests to `/v1`.
- Build updates email form (Phase 6) posts straight to an external newsletter tool (such as Buttondown). HQ never sees or stores the address.
